# Министерство любви

[English version](README.md)

Telegram-бот для групповых чатов, который работает свахой. Участники
добавляют персонажей (людей из чата, вымышленных героев, кого угодно),
а бот выбирает «пару дня», придумывает случайные свидания и подбирает
пару заданному персонажу. К парам прилагается подарок из набора,
который выбирает чат.

## Запуск

### 1. Создайте бота и заполните `.env`

1. Создайте бота через [@BotFather](https://t.me/BotFather) и скопируйте токен.
2. Скопируйте `.env.example` в `.env` и впишите токен в `TOKEN`.
3. `OWNER_ID` пока оставьте пустым и запустите бота (следующий шаг).
4. Отправьте боту `/myid`, впишите полученное число в `OWNER_ID` и
   перезапустите бота. После этого `/myid` отвечает только вам и видна
   только в вашем меню команд.

| Переменная     | Обязательна | По умолчанию                       | Что это                       |
|----------------|-------------|------------------------------------|-------------------------------|
| `TOKEN`        | да          | —                                  | Токен бота от @BotFather      |
| `OWNER_ID`     | нет         | пусто (`/myid` доступна всем)      | Ваш Telegram ID               |
| `DATABASE_URL` | нет         | `sqlite:///data/committee.db`      | Любой URL для SQLAlchemy      |

### 2а. Через Docker (рекомендуется)

Если Docker на Windows ещё не установлен, начните с раздела
[Установка Docker в Windows](#установка-docker-в-windows).

```sh
docker compose up -d --build
docker compose logs -f bot
```

База SQLite хранится в томе `bot-data` (`/app/data` в контейнере) и
переживает пересборку. Контейнер перезапускается сам, пока вы его не
остановите.

### 2б. Локально

Нужен Python 3.12+ (код использует `enum.StrEnum`).

```sh
python -m venv .venv
.venv\Scripts\activate        # Windows; в Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
python bot.py
```

База создаётся в `data/committee.db` рядом с `bot.py`.

На один токен запускайте только одну копию бота. Telegram разрешает
только одного клиента long polling, поэтому локальная копия и копия в
Docker, запущенные одновременно, будут отбирать друг у друга обновления.

## Установка Docker в Windows

Docker в Windows работает поверх WSL 2 (Windows Subsystem for Linux).
Нужна 64-битная Windows 10 22H2 или Windows 11 и права администратора.

### 1. Проверьте, что включена виртуализация

Откройте Диспетчер задач → Производительность → ЦП и найдите строку
**Виртуализация: Включено**. Если там «Отключено», включите Intel VT-x
или AMD-V (SVM) в настройках BIOS/UEFI.

### 2. Установите WSL 2

Откройте PowerShell **от имени администратора** и выполните:

```powershell
wsl --install
```

Команда включит нужные компоненты Windows, установит ядро WSL 2 и
дистрибутив Ubuntu. Когда попросит, перезагрузите компьютер.

После перезагрузки Ubuntu откроется сама (или запустите её из меню
«Пуск») и попросит придумать имя пользователя и пароль Linux. Они не
связаны с учётной записью Windows; пароль запомните, его будет
спрашивать `sudo`.

Проверьте результат:

```powershell
wsl --update
wsl -l -v
```

В колонке `VERSION` у Ubuntu должно быть `2`. Если там `1`, выполните
`wsl --set-version Ubuntu 2`.

### 3. Установите Docker Desktop

1. Скачайте Docker Desktop для Windows со страницы
   [docs.docker.com/desktop/setup/install/windows-install](https://docs.docker.com/desktop/setup/install/windows-install/)
   и запустите установщик.
2. Оставьте включённым пункт **Use WSL 2 instead of Hyper-V**.
3. После установки выйдите из учётной записи Windows и войдите снова
   (или перезагрузитесь).
4. Запустите Docker Desktop и примите лицензию. Входить в аккаунт Docker
   не обязательно.
5. Чтобы `docker` работал и из терминала Ubuntu, откройте Settings →
   Resources → WSL integration и включите Ubuntu.

Docker Desktop бесплатен для личного использования, обучения и небольших
компаний (меньше 250 сотрудников и меньше $10 млн выручки). Крупным
компаниям нужна платная подписка; если это ваш случай, смотрите вариант
ниже.

### 4. Проверьте, что Docker работает

В PowerShell (Docker Desktop должен быть запущен):

```powershell
docker --version
docker compose version
docker run --rm hello-world
```

Если `hello-world` вывел «Hello from Docker!», всё готово. Перейдите в
папку проекта и продолжайте с [шага 2а](#2а-через-docker-рекомендуется).

### Другой вариант: Docker Engine внутри WSL, без Docker Desktop

После шага 2 откройте терминал Ubuntu и выполните:

```sh
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER
```

Закройте терминал, выполните `wsl --shutdown` в PowerShell, снова
откройте Ubuntu и проверьте: `docker run --rm hello-world`. В этом
варианте все команды `docker` запускаются из Ubuntu, а не из
PowerShell. Диски Windows лежат в `/mnt`, например `C:\fundev` — это
`/mnt/c/fundev`, но сборка идёт быстрее, если склонировать проект в
домашнюю папку Linux (`~`).

Если `docker` не может подключиться к демону, возможно, выключен
systemd. Добавьте в `/etc/wsl.conf` в Ubuntu эти строки, затем выполните
`wsl --shutdown` и снова откройте Ubuntu:

```ini
[boot]
systemd=true
```

## Как пользоваться в чате

Добавьте бота в группу, затем:

1. `/start` — при первом запуске бот попросит выбрать набор подарков.
2. `/standard` — встроенные подарки, или `/custom` — свой набор, который
   собирается командами `/addgift <название>` и `/deletegift <название>`.
3. `/add <имя>` — добавить персонажа. После этого бот попросит фото:
   ответьте на его сообщение картинкой. Позже фото можно добавить или
   заменить через `/addphoto <имя>`.
4. Играйте: `/pair`, `/random`, `/match <имя>`.

### Команды

| Команда                  | Что делает                                              |
|--------------------------|---------------------------------------------------------|
| `/start`                 | Приветствие; просит выбрать набор подарков, если его нет |
| `/help`, `/info`         | Список команд, информация о боте                        |
| `/pair`                  | Пара дня                                                |
| `/random`                | Случайное свидание                                      |
| `/match <имя>`           | Случайная пара для персонажа                            |
| `/add <имя>`             | Добавить персонажа (затем ответить фото)                |
| `/addphoto <имя>`        | Запросить новое фото персонажа                          |
| `/delete <имя>`          | Удалить персонажа                                       |
| `/characters`            | Список персонажей                                       |
| `/gifts`                 | Текущий набор подарков                                  |
| `/standard`              | Стандартный набор подарков                              |
| `/custom`                | Свой набор подарков чата                                |
| `/addgift <название>`    | Добавить подарок (только в своём наборе)                |
| `/deletegift <название>` | Удалить подарок (только в своём наборе)                 |
| `/myid`                  | Ваш Telegram ID (только владельцу, если задан `OWNER_ID`) |

## Как это устроено

### Всё хранится отдельно для каждого чата

У каждой группы свои персонажи, набор подарков и пара дня. Все данные
привязаны к ID чата.

Имена персонажей и названия подарков сравниваются без учёта регистра,
лишние пробелы схлопываются (`normalize_name` в
[ministry/models.py](ministry/models.py)), поэтому `/delete иван  петров`
найдёт «Иван Петров». Внутри чата имена уникальны. Ограничения: 64
символа на имя персонажа, 100 на название подарка.

### Наборы подарков

Сначала у чата нет набора (`unset`). `/standard` включает встроенный
список из [ministry/content.py](ministry/content.py), `/custom` — свои
подарки чата из базы. При возврате к стандартному набору свои подарки
не удаляются, к ним можно вернуться. Добавлять и удалять подарки можно
только в режиме своего набора.

### Пара дня (`/pair`)

Первый `/pair` за день выбирает двух случайных персонажей и фразу с
подарком и сохраняет их (одна строка `daily_pairs` на чат,
перезаписывается каждый день). Остальные вызовы в тот же день
возвращают ту же пару. День сменяется в полночь по Москве (UTC+3,
`PAIR_TIMEZONE` в [ministry/constants.py](ministry/constants.py)). Если
одного из пары удалить, пара удаляется вместе с ним, и следующий
`/pair` выберет новую.

Если набор подарков не выбран или свой набор пуст, вместо подарка
выводится строка «без подарка».

### Случайное свидание (`/random`)

Нужно минимум два персонажа. Каждый вызов разыгрывает:

- 10% — персонаж идёт на свидание сам с собой;
- 10% — персонаж остаётся дома;
- 80% — история из `DATE_SCENARIOS`. Некоторым историям нужно 3 или 4
  персонажа, они выпадают только если в чате столько есть. Если
  подарков нет, используется запасной («полевой букетик»).

Ничего не сохраняется, каждый вызов — новый розыгрыш. Вероятности и
истории лежат в [ministry/content.py](ministry/content.py).

### Подбор пары (`/match <имя>`)

Ставит указанного персонажа в пару со случайным другим. Ничего не
сохраняется.

### Фото

Если у персонажа есть фото, оно прикладывается к результату: два фото
уходят альбомом с текстом в подписи, одно — картинкой с подписью. Бот
хранит только `file_id` из Telegram, а не само изображение.

Фото принимается, только если оно отправлено ответом на последнее
сообщение бота «пришлите фото» для этого пользователя в этом чате. Такие
запросы хранятся в памяти и теряются при перезапуске бота; в этом случае
выполните `/addphoto <имя>` ещё раз.

## Структура кода

```
bot.py                  точка входа: логи, инициализация БД, хендлеры, polling
ministry/
  constants.py          настройки из .env
  db.py                 движок и сессии SQLAlchemy; создаёт таблицы при старте
  models.py             таблицы: chats, characters, gifts, daily_pairs
  texts.py              все сообщения бота и описания команд
  content.py            стандартные подарки, фразы, сценарии свиданий, вероятности
  handlers/             слой Telegram: разобрать команду, вызвать сервис, ответить
  services/             логика и работа с БД, без кода Telegram
```

Хендлеры тонкие: читают аргумент команды, открывают сессию, вызывают
сервис и превращают его исключения (`NotFound`, `AlreadyExists`,
`NameTooLong`, ...) из [ministry/services/errors.py](ministry/services/errors.py)
в ответы.

Таблицы создаются через `create_all` при старте. Миграций нет: если
меняете модель, обновите существующую базу вручную или удалите её.

Тексты бота правятся в [ministry/texts.py](ministry/texts.py), подарки и
истории свиданий — в [ministry/content.py](ministry/content.py).
